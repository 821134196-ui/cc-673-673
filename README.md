# 培养皿污染隔离与观察系统

实验室培养皿疑似污染时的**隔离 → 同箱暴露筛选 → 分样本观察/复检 → 废弃**全流程系统。

- 后端：PHP 8.x · Laravel · Eloquent · **SQLite**
- 前端：React 18 · Vite · React Router
- 照片：本地磁盘保存（`storage/app/public`，经 `/storage` 提供）
- 提醒：本地模拟（REST 接口 + Artisan 命令，不接外部通道）
- 角色：**实验员**（登记/观察/废弃）与**负责人**（判定同箱样本是否受影响），页面右上角切换身份（本地模拟登录）

## 一条命令启动

```bash
./start.sh
```

脚本会自动：下载静态 PHP 运行时（机器无 PHP 时，仅首次）→ 安装 Composer/npm 依赖 →
配置 SQLite、执行迁移与演示数据 → 同时启动前后端。

- 前端页面：<http://localhost:5173>
- 后端 API：<http://127.0.0.1:8000/api>
- 停止：`Ctrl+C`

> 机器上已有原生 PHP 8.2+ 时会自动优先使用；无 root 权限也可运行（运行时装在 `~/.local/`）。

复检提醒（本地模拟命令）：

```bash
cd backend && php artisan lab:retest-remind          # 默认未来 2 天内到期
php artisan lab:retest-remind --days=7               # 扩大窗口
```

对应接口：`GET /api/reminders`。

## 业务规则

### 1. 隔离登记（实验员）
登记**来源样本、培养箱、可疑时间段**，提交后来源样本立即进入隔离并设定复检截止日（默认 7 天，可改）。

### 2. 同箱暴露筛选（系统 + 负责人判定）
唯一依据是 `storage_events`（样本在某培养箱的实际存放区间）与可疑时间段是否**严格重叠**：

```
重叠条件：同培养箱 AND started_at < 窗口结束 AND (ended_at > 窗口开始 OR 仍在箱)
```

- 可疑时间段**结束后才放入**的样本 → 不筛出；
- 可疑时间段**开始前已取出**的样本 → 不筛出；
- 仅时间点相接（放入时刻 = 窗口结束）→ 不算共同存放；
- 其他培养箱的样本 → 不筛出。

筛出的候选展示共同存放交集（快照），由**负责人**逐条判定「受影响（自动隔离）/未受影响」。
实验员调用判定接口返回 403。补充存放记录后可点「重新扫描」。

### 3. 领用拦截
隔离中（`quarantined`）、复检未通过继续冻结（`frozen`）、已废弃（`discarded`）的样本
领用到后续实验一律拦截（HTTP 409，不产生领用记录）；仅在库与复检通过放行的样本可领用。

### 4. 每个样本独立结论
观察 / 复检通过 / 复检未通过 / 废弃均按样本分别登记，互不影响：

- **复检未通过**：样本继续冻结，且必须给出下一次复检截止日；
- **复检通过**：放行，可领用；
- **废弃**：必须记录处理方式与执行人；废弃后**原批次号与全部观察/照片历史保留**，
  但不能再登记结论或领用。

## 页面

| 页面 | 功能 |
|---|---|
| 样本 | 卡片式列表，隔离/冻结卡片红色突出并显示**复检截止日/逾期**；登记新样本 |
| 样本详情 | 顶部横幅突出隔离状态与复检截止日；存放历史、领用、结论登记、照片、时间线 |
| 培养箱与存放 | 维护培养箱；按时间段登记样本放入/取出 |
| 隔离登记 | 实验员登记可疑事件；详情页由负责人判定同箱候选 |
| 复检提醒 | 临近/逾检样本列表（本地模拟） |

## 主要 API

```
POST   /api/samples                         登记样本
POST   /api/storage-events                  登记存放时间段
POST   /api/isolations                      登记隔离（自动筛同箱候选）
GET    /api/isolations/{id}                 隔离详情 + 候选及交集快照
POST   /api/isolations/{id}/rescan          重新扫描
POST   /api/exposures/{id}/decide           负责人判定（manager only）
POST   /api/samples/{id}/observations       观察/复检/废弃结论（multipart，可带 photos[]）
POST   /api/samples/{id}/checkout           领用（隔离/冻结/废弃返回 409）
GET    /api/reminders                       复检提醒（本地模拟）
```

所有接口通过 `X-Actor-Id` 请求头指定当前操作人（种子数据：1=实验员，2=负责人）。

## 演示数据

种子数据围绕培养箱 INC-A1、可疑窗口 `2026-10-04 00:00 ~ 2026-10-05 00:00`：

- **P-001** 疑似污染源（窗口内外在箱）
- **P-002** 窗口内同箱（10-04 12:00~20:00）→ 唯一被筛出
- **P-003** 10-05 09:00 才放入 → 不筛出
- **P-004** 10-03 20:00 已取出 → 不筛出
- **P-005** 一直在 INC-B2 → 不筛出

## 测试

```bash
cd backend && php vendor/bin/phpunit
```

`tests/Feature/LabWorkflowTest.php` 覆盖并断言：

1. **同箱时间范围筛选**——窗口内入选，后来放入/之前取出/异箱/时间点相接全部排除，交集快照正确；
2. **隔离期间领用拦截**——隔离 409、复检未通过冻结 409、放行后 201，且冻结必须给新截止日；
3. **不同样本独立结论**——A 放行与 B 废弃互不影响，角色 403，废弃后批次/历史保留且禁止继续操作；
4. 提醒接口与 `lab:retest-remind` 命令。
